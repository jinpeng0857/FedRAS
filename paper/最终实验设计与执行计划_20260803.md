# FedDR 实验执行计划（最终固定配置版）

> 本文件只保留最终确定的实验配置、已完成结果和后续正式复现实验步骤。

## 1. 实验目标

实验围绕一个主方法和三个问题展开：

\`\`\`
FedACG checkpoint
      ↓
DLRS：样本可靠性控制区域尺度 + 联合软加权
      ↓
FSLR：Fisher×Drift 周期稀疏恢复
      ↓
FedDR deployment TTA
\`\`\`

需要回答：

1. 在同一 FedACG 初始化和同一 CIFAR-100-C 流程下，FedDR 与 TTA 基线的差异是什么？
2. DLRS 的样本—区域联合权重和 FSLR 的漂移感知恢复分别贡献多少？
3. 固定 FedDR 适配器换用不同联邦优化器 checkpoint 后，结论是否仍成立？

## 2. 不变的实验协议

以下变量在 FedDR 主结果、组件验证和联邦初始化补充中预先锁定；外部基线保留其已声明的官方配置并单独登记。

| 项目 | 正式设置 |
|---|---|
| 数据集 | CIFAR-100-C，severity 5 |
| 主模型 | ResNet-18 |
| 客户端训练 | 100 clients，Dirichlet alpha=0.3，equal-size，join ratio=0.15 |
| FedDR batch | 128；worker=2 |
| corruption | 15 类固定代码顺序 |
| Domain-wise | 每个 corruption 重建 model/optimizer/adapter/restorer |
| Continual | 15 类 × 3 cycle，持续继承状态 |
| 预测口径 | 当前 batch 先预测、再更新；准确率使用更新前原图输出 |
| 适配参数 | FedDR/DLRS/FSLR 为全部 BN affine |
| FedDR optimizer | SGD，lr=5e-4，momentum=0.9，weight decay=0 |
| DLRS | 全样本软可靠性加权；`alpha=0.7`，PLPD reference=0.2，区域尺度 `[0.6,1.2]`，`lambda_RI=0.5` |
| FSLR | interval=5，strength=0.9，drift-tiered，阈值 0.10/0.20/0.35，比例 0/0.02/0.05/0.30，可靠性阈值 0.55，EMA decay 0.90 |
| 统计 | 主 Fisher；feature samples=500；统计文件与 checkpoint 一一对应 |
| 正式截断 | \`max_batches=-1\`，完整流 |

正式顺序为：\`gaussian_noise, shot_noise, impulse_noise, defocus_blur, glass_blur, motion_blur, zoom_blur, snow, frost, fog, brightness, contrast, elastic_transform, pixelate, jpeg_compression\`。流结束后的 clean 和前四域回访阶段禁止再次适配。

### 2.1 当前固定结果

FedACG run1（`model_round499.pt`，`lookahead_anchor`）在上述协议下的已完成结果为：

| Domain-wise mean | Continual mean | Clean retention | Revisit mean | Final BN-affine drift |
|---:|---:|---:|---:|---:|
| 60.80% | 62.11% | 75.51% | 56.19% | 0.3153 |

该行是当前唯一固定的 FedDR 结果，来源为完整 15 域、3-cycle、predict-then-update 的 run1 评测。它是单个 checkpoint 的证据，不写成多重复均值；正式论文表格在完成声明的训练/测试重复后再补 `mean ± std`。

## 3. 结果单位与重复设计

### 3.1 独立重复

独立重复单位是“联邦训练种子/客户端划分 → checkpoint → 统计文件 → 完整 TTA 流”：

| 重复 | 训练 seed | dataset seed | new dataset seed | 用途 |
|---|---:|---:|---:|---|
| run1 | 42 | 21 | 30 | 主结果 |
| repeat-52 | 52 | 对应匹配划分 | 对应匹配划分 | 主结果重复 |
| repeat-62 | 62 | 对应匹配划分 | 对应匹配划分 | 扩展重复 |

当前仓库已明确提供 run1 和 seed52 的 FedACG launcher 路径；seed62 需先确认 checkpoint 存在再纳入正式汇总。15 个 corruption、3 个 cycle 和 batch 数均不是独立重复。

### 3.2 测试随机性

DLRS 的 patch shuffle 和 CoTTA 的增强带来测试随机性。正式执行时为每个“方法 × checkpoint”跑测试 seed 0、1、2；先在 checkpoint 内取测试 seed 均值，再在 checkpoint 之间报告 \`mean ± std\`。若只完成一个测试 seed，结果只能标为预检查，不得冒充三次重复结果。

## 4. 阶段 0：执行前静态检查（不运行模型）

1. 确认仓库根目录、当前 Python/conda 环境和 GPU 可见性。
2. 读取 \`main_test.py\`、\`prepare_main_statistics.py\`、\`sparse_restore.py\` 和所有 launcher 的 Git 版本；记录 commit 或文件 hash。
3. 检查每个模型 checkpoint、CIFAR-100-C 目录和输出目录是否存在。
4. 检查 checkpoint 的 anchor key：FedACG 用 \`lookahead_anchor\`，其他联邦优化器用 \`adaptation_anchor\`。
5. 检查没有把旧统计文件错配给新 checkpoint；文件名必须包含 federated method、run 和 seed。
6. 检查正式命令的 \`max_batches=-1\`，并固定 \`CUDA_VISIBLE_DEVICES\`、数据根目录和输出路径。

阶段 0 的产物是 \`preflight_manifest.json\` 或等价清单，不改变第 2 节固定配置。

## 5. 阶段 1：联邦初始化 checkpoint

### 5.1 主 checkpoint

先使用已有 FedACG run1 和 seed52 checkpoint。若要生成 seed62，使用与 run1 相同的训练配置，仅替换训练和数据划分种子。

### 5.2 联邦补充 checkpoint

在主 TTA、机制消融和重复完成后，再执行 \`train/train_federated_supplements.sh\`。该脚本只训练 FedAvg/FedProx/SCAFFOLD/FedDyn/FedAdam 初始化，不执行 TTA。

补充训练的代码配置为：500 global rounds、3 local epochs、batch 64、cosine scheduler、local lr decay 0.998、label smoothing 0.1、RandAugment(n=2,m=9)、AMP、BN enabled。各优化器特有参数由脚本固定：

| 算法 | 关键参数 |
|---|---|
| FedAvg | lr=.05，momentum=.9，wd=.0005 |
| FedProx | FedAvg 配置，mu=.01 |
| SCAFFOLD | lr=.1，server_lr=1，momentum=0，wd=0 |
| FedDyn | lr=.05，alpha=.01，momentum=0，wd=.0005 |
| FedAdam | lr=.05，beta1=.9，beta2=.999，tau=.001，server_lr=1 |

每个联邦算法必须保存最终 checkpoint、训练日志、配置快照和 clean 检查点记录。只存在 checkpoint 而没有配置/日志时，不能进入补充表。

## 6. 阶段 2：为每个 checkpoint 生成离线统计

对每个 checkpoint 单独执行以下两类统计。TTA 对比方法的统计文件统一写入
`test/outputs/`；FedDR 主方法及其联邦初始化补充评测的统计文件写入根目录
`outputs/`，避免两类产物混放。

### 6.1 FedDR、Source、Tent、ReCAP、DeYO、CoTTA

\`\`\`bash
python prepare_main_statistics.py \
  --dataset cifar100 \
  --model_path <checkpoint> \
  --anchor_key <lookahead_anchor|adaptation_anchor> \
  --data_root data \
  --feature_samples 500 \
  --fisher_max_batches -1 \
  --fisher_mode main \
  --fisher_samples -1 \
  --batch_size 128 --num_workers 2 --seed 0 --device cuda \
  --output_path <test/outputs 或 outputs>/<method>_<run>_statistics.pt
\`\`\`

### 6.2 EATA

\`\`\`bash
python prepare_main_statistics.py \
  --dataset cifar100 \
  --model_path <checkpoint> \
  --anchor_key <anchor_key> \
  --data_root data \
  --feature_samples 500 \
  --fisher_max_batches -1 \
  --fisher_mode eata_official \
  --fisher_samples 2000 \
  --batch_size 64 --num_workers 2 --seed 0 --device cuda \
  --output_path test/outputs/<method>_<run>_eata_statistics.pt
\`\`\`

生成后静态核对 statistics payload 的 dataset、model、anchor key、classes、feature sample count 和 Fisher mode。统计文件只服务于生成它的 checkpoint。

## 8. 阶段 4：FedDR 机制验证

只在 FedACG 主 checkpoint 和声明的独立训练重复上执行。所有数值超参数固定为第 2 节配置，只切换方法组件：

| 实验 | 改动 | 目的 |
|---|---|---|
| A | 无 DLRS、无 FSLR | base adaptation |
| B | DLRS、无 FSLR | DLRS 组件 |
| C | DLRS + FSLR | 完整 FedDR |

每次验证只改变一个方法组件；保持 anchor、统计文件、数据顺序、batch size、优化器、更新范围和测试 seeds 不变。输出必须包含 DLRS counters 与 FSLR restoration 字段。

## 9. 阶段 5：联邦优化器补充实验

使用同一个 \`main_test.py --tta_method feddr\`，只替换 \`--federated_method\`、checkpoint 和对应 statistics：

\`\`\`bash
python main_test.py \
  --dataset cifar100 \
  --federated_method <fedavg|fedprox|scaffold|feddyn|fedadam> \
  --model_path <checkpoint> \
  --anchor_key adaptation_anchor \
  --tta_method feddr \
  --statistics_path outputs/<matching_statistics>.pt \
  --cifar_c_path data/CIFAR-100-C --clean_data_root data \
  --device cuda --batch_size 128 --num_workers 2 \
  --adapt_lr 0.0005 --momentum 0.9 --weight_decay 0.0 \
  --recovery_interval 5 --restore_strength 0.9 \
  --restore_budget_mode drift_tiered \
  --restore_drift_thresholds 0.10 0.20 0.35 \
  --restore_drift_ratios 0.0 0.02 0.05 0.30 \
  --seed <test_seed> --max_batches -1 \
  --output_path outputs/feddr_<federated_method>_<run>_<test_seed>.json
\`\`\`

补充表报告：联邦算法 clean checkpoint、FedDR domain-wise/continual accuracy、clean retention、回访准确率和恢复统计。该表回答“初始化来源是否影响部署适配”，不把 FedAvg 等当成 TTA 方法与 Tent 直接并列。

## 10. 阶段 6：汇总与统计

1. 读取每个 JSON 的 \`domain_wise\`、\`continual\`、\`clean_retention\`、\`restoration\`；固定 run1 结果按第 2.1 节登记。
2. 在每个 checkpoint 内先聚合 corruption，再聚合 cycle；不得把 batch 行直接当独立实验样本。
3. 对测试 seed 取均值；再对训练 checkpoint 取均值和标准差。
4. 主结果至少报告：15 域平均、cycle 1/2/3、最后 cycle、clean retention、四域回访、平均熵、更新/非有限 batch、恢复比例和时间。
5. 对 FedDR 增加 reliability、region scale、joint weight、drift before/after、selected drift energy 和 selection Jaccard；不引入样本级归因贡献字段。
6. 任何缺少 \`schema_version=9\`、anchor 校验、完整 corruption 数量或 restoration payload 的 JSON 标为无效，不进入表格。

## 11. 阶段 7：审计和停止条件

### 11.1 通过条件

- 每个正式 JSON 都能追溯到唯一 checkpoint、anchor key、statistics 文件和 launcher 参数。
- Domain-wise 恰有 15 个 corruption；continual 恰有 3 个 cycle；回访恰为前四域。
- \`evaluate_post_stream\` 阶段没有参数、batch counter 或 restorer counter 变化。
- FedDR 日志显示 selected count 等于 batch size，证明没有硬门控；joint weight 和 region scale 为有限值。
- FSLR 触发记录与 interval、budget mode、drift thresholds 一致。
- 三个联邦训练重复与三个测试随机种子的聚合关系在汇总表中明确。
- 结果中的 SAR/RoTTA/PeTTA/REM 只在 adapter 接入并完成完整流后出现。

### 11.2 必须停止并修复的情况

- checkpoint 与 statistics 的 dataset/model/anchor/classes 不匹配；
- 15 域顺序、severity、batch size 或 \`max_batches\` 被改变；
- 只生成了一个 checkpoint 却声称有多次独立重复；
- SAR/RoTTA/PeTTA/REM 尚无 adapter 却被填入结果；
- post-stream 发生更新；
- JSON 缺少 schema version、方法名或关键 counters；
- 任何 NaN/Inf loss、梯度或参数未被记录并解释。

## 12. 官方 launcher 与执行顺序

正式执行顺序固定为：

1. 静态 preflight 与清单；
2. 确认/生成 FedACG checkpoint；
3. 为 FedACG checkpoint 生成 main/EATA statistics；
4. 运行 Source/Tent/EATA/CoTTA/FedDR 可运行主表；
5. 运行 DLRS/FSLR/ReCAP 机制消融；
6. 生成并审计 FedAvg/FedProx/SCAFFOLD/FedDyn/FedAdam checkpoint；
7. 运行联邦初始化补充表；
8. 扩展第三训练重复和测试 seeds；
9. 汇总 JSON、审计数量和导出论文表格。

对应入口是：

\`\`\`bash
# 主 FedDR 与联邦初始化补充评测（只在确认 checkpoint 后执行）
bash feddr_main.sh

# Source/Tent/EATA/CoTTA/FedDR 以及 DeYO/ReCAP 机制参照
bash test/comparison_all.sh

# FedAvg/FedProx/SCAFFOLD/FedDyn/FedAdam 联邦训练补充
bash train/train_federated_supplements.sh
\`\`\`

主 FedDR 固定配置已经在 \`main_test.py\` 与 \`feddr_main.sh\` 中锁定，且第 2.1 节结果已完成。上述命令是后续可运行主表、固定组件验证、联邦初始化补充及多重复汇总的入口；在多重复完成前，不把单次 run1 写成最终统计结论。
